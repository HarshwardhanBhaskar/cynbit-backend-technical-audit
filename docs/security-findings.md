> **Standards Referenced:** OWASP Top 10 (2021), OWASP ASVS v4.0, NIST SP 800-63B, CWE Top 25  
> **Classification Standard:** Strictly separates Verified Observations from Potential Risks and Architectural Recommendations.

## 1. Security Architecture Evaluation & Recommendations

### 1.1 Password Hashing & Credential Security
* **Industry Standard:** NIST SP 800-63B mandates adaptive memory-hard hashing algorithms.
* **Recommendation:** Use **Argon2id** (m=65536, t=3, p=4) or **bcrypt** (work factor $\ge 12$).
* **Storage Rules:**
  - Never store plain text or unsalted SHA-256/MD5 hashes.
  - Implement per-user cryptographic salt generated by a cryptographically secure pseudo-random number generator (CSPRNG).
  - Rate-limit credential verification endpoints to mitigate offline and online dictionary attacks.

### 1.2 Session Management & JWT Token Architecture
* **Access Tokens:** Short-lived JSON Web Tokens (15–30 minutes expiration), signed with asymmetric RS256/EdDSA or high-entropy HS256 ($\ge 256$ bits secret).
* **Refresh Tokens:** Long-lived tokens (7–14 days) stored securely in `HttpOnly`, `Secure`, `SameSite=Strict` cookies.
* **Token Rotation & Revocation:**
  - Implement single-use refresh token rotation: every refresh invalidates the prior token and issues a new pair.
  - If a previously used refresh token is presented, trigger family invalidation (flag potential token theft).
  - Maintain a Redis-backed token blacklist/revocation registry for immediate session revocation upon logout or password reset.

### 1.3 Access Control & Role-Based Authorization (RBAC)
* Implement principle of least privilege.
* Granular permission scopes: e.g., `applicant:submit`, `candidate:read`, `admin:review`.
* Enforce server-side authorization checks on every endpoint using dependency injection, rather than client-controlled parameters.

### 1.4 Rate Limiting & Abuse Prevention
* **Global Edge Limiting:** Cloudflare / WAF level rate limiting against volumetric attacks.
* **Application Layer Limiting:** Distributed Redis sliding-window algorithm:
  - Career Application Submissions: 5 requests / hour / IP (protects talent acquisition database).
  - Contact Form Submissions: 5 requests / hour / IP (mitigates spam).
  - Authentication Endpoints: 5 attempts / 15 minutes / IP (blocks credential stuffing).

### 1.5 Cross-Origin Resource Sharing (CORS) & CSRF Defense
* **CORS:** Restrict `Access-Control-Allow-Origin` explicitly to `https://cynbit.in` and approved subdomains. Disallow wildcard `*` when credentials/cookies are permitted.
* **CSRF Protection:**
  - Enforce `SameSite=Lax` or `SameSite=Strict` on session cookies.
  - Require anti-CSRF synchronizer tokens on state-changing non-idempotent HTTP methods (`POST`, `PUT`, `DELETE`).
  - Next.js Server Actions enforce Origin header verification by default.

### 1.6 Secure HTTP Response Headers
All HTTP responses should include defense-in-depth security headers:

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' https://www.googletagmanager.com; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; connect-src 'self' https://www.google-analytics.com;
```

### 1.7 Sensitive Data & PII Protection (India DPDP Act 2023)
* Candidate date of birth, phone numbers, resumes, and academic transcripts constitute personal data.
* **Storage Encryption:** Enforce AES-256 column-level encryption or transparent data encryption (TDE) at rest.
* **Transit Encryption:** Enforce TLS 1.3 exclusively.
* **Data Minimization:** Retain applicant data only for the duration of the hiring cycle unless consent is renewed.

### CYN-SEC-001: Public Disclosure of Direct Corporate Email Addresses
* **Category:** Information Exposure (CWE-200)
* **Severity:** Informational
* **Confidence:** 100% (High)
* **Verification Status:** [VERIFIED OBSERVATION]
* **Evidence:** The contact page (`/contact`) visibly publishes `opportunities@cynbit.in` and `support@cynbit.in`.
* **Impact:** Publicly exposed mailboxes are harvested by automated scrapers, resulting in increased spam, targeted phishing, and business email compromise (BEC) vectors.
* **Recommendation:** Transition to authenticated contact form routing; implement Cloudflare email address obfuscation and strict SPF/DKIM/DMARC policies.

---

### CYN-SEC-002: Next.js Frontend Framework and RSC Telemetry Identifiers
* **Category:** Technology Fingerprinting (CWE-200)
* **Severity:** Informational
* **Confidence:** 100% (High)
* **Verification Status:** [VERIFIED OBSERVATION]
* **Evidence:** Network chunk distribution (`/_next/static/chunks/...`) and RSC header payloads observed in Chrome DevTools.
* **Impact:** Discloses framework ecosystem, enabling threat actors to cross-reference framework-specific CVE databases.
* **Recommendation:** Suppress custom `x-powered-by` headers in `next.config.js` (`poweredByHeader: false`) and ensure rapid deployment of upstream security patches.

---

### CYN-SEC-003: Client-Side Native Validation on Application Form Without Observable Backend Safeguards
* **Category:** Input Validation (CWE-20 / OWASP A03:2021 – Injection)
* **Severity:** Medium
* **Confidence:** 70% (Medium)
* **Verification Status:** [POTENTIAL RISK]
* **Evidence:** HTML inspection of `/careers/backend-developer-intern` reveals standard HTML5 tags (`required`, `type="email"`, `type="tel"`). Backend validation endpoints could not be verified without active submission.
* **Impact:** If backend services rely solely on client-side constraints, malicious actors can craft raw HTTP requests containing injection payloads, oversized strings, or corrupt types.
* **Recommendation:** Implement robust Pydantic schemas validating every input field on the server, enforcing regex formats, length boundaries, and type coercion.

---

### CYN-SEC-004: Absence of Visible Rate Limiting on Talent Acquisition Endpoints
* **Category:** Denial of Service / Resource Exhaustion (CWE-400 / OWASP A04:2021)
* **Severity:** Medium
* **Confidence:** 65% (Medium)
* **Verification Status:** [POTENTIAL RISK]
* **Evidence:** Public application modal accepts unauthenticated input submissions; passive inspection identified no visible CAPTCHA (Turnstile / reCAPTCHA).
* **Impact:** Unprotected forms are vulnerable to automated bot flooding, database record pollution, and storage exhaustion.
* **Recommendation:** Deploy Cloudflare Turnstile bot verification alongside Redis-backed IP/session sliding window rate limiters.

---

### CYN-SEC-005: Terms and Conditions Consent Checkbox Lacks Cryptographic Audit Trail
* **Category:** Security & Compliance Auditability (OWASP A09:2021)
* **Severity:** Low
* **Confidence:** 80% (High)
* **Verification Status:** [POTENTIAL RISK]
* **Evidence:** Consent checkbox `agreedToTerms` is a client boolean. Backend audit schema must store consent timestamp, IP address, user-agent, and terms policy version.
* **Impact:** Insufficient non-repudiation in the event of candidate data processing disputes under DPDP regulations.
* **Recommendation:** Store immutable audit event records (`audit_events` table) capturing timestamp, consent hash, terms version ID, and client IP.

### CYN-SEC-006: HTTP Security Headers Configuration Not Verified

* **Severity:** Low

### CYN-SEC-009: Resume & Portfolio External Links Handling
* **Category:** Insecure File Upload / SSRF (CWE-434 / CWE-918)
* **Severity:** Medium
* **Confidence:** 65% (Medium)
* **Verification Status:** [RECOMMENDATION]
* **Evidence:** Application form includes fields for Resume / Portfolio URL.
* **Impact:** If the backend attempts to fetch or download candidate URLs without validation, it is vulnerable to Server-Side Request Forgery (SSRF) against internal metadata services (`169.254.169.254`). If direct file uploads are permitted, malicious PDFs could execute shellcode.
* **Recommendation:** Restrict external links to standard HTTPS schemes; block internal IP ranges (RFC 1918, RFC 3927); if file uploads are implemented, use S3 pre-signed upload URLs and scan with ClamAV.
